States im Studio

Hover, Focus und Custom-States im Code editieren, im Run-Mode prüfen

Kapitel 6 zeigt die States-Syntax in der DSL — hover:, on:, toggle(). Hier geht es um den Studio-Workflow dazu: States schreibst du heute direkt im Code-Editor (das Property-Panel hat dafür noch keine Tabs), und siehst die Wirkung im Run-Mode (Kapitel 26) oder im Browser-Hover.

System-States im Code

System-States (hover, focus, active, disabled) schreibst du direkt unter die Element- oder Komponenten-Definition. Einrückung zählt: was unter hover: eingerückt ist, gilt nur im Hover-Zustand. 

Btn: bg #333, col white, pad 10 20, rad 6
  hover:
    bg #444
  focus:
    bor 2, boc #2271C1
  disabled:
    opacity 0.5, cursor not-allowed

Im Preview siehst du Hover sofort beim Maus-Hover; Focus triggerst du mit Tab oder Klick auf ein Input. Disabled setzt du im Code via Instanz-Property: Btn "Senden", disabled.

Custom-States mit toggle()

Eigene Zustände definierst du genauso — gib dem State einen Namen (z. B. on, active, highlighted) und schreibe einen name:-Block. Damit der State bei Klick wechselt, ergänzt du toggle() als Property auf der Definition: 

LikeBtn: bg #333, col #888, pad 12 20, rad 6, hor, gap 8, toggle()
  Icon "heart", ic #888, is 18
  Text "Gefällt mir"
  on:
    bg #ef4444
    col white
    Icon "heart", ic white, is 18, fill
    Text "Gefällt mir!"

Bei mehreren Custom-States cyclet toggle() reihum. Mit exclusive() statt toggle() bekommst du Tab-/Radio-Verhalten: nur ein Element in der Gruppe ist gleichzeitig aktiv.

Cross-Element-State

Ein Element kann auf den State eines anderen Elements reagieren. Du gibst dem Trigger-Element einen name und das Reaktiv-Element trägt einen Trigger.state:-Block: 

Button name MenuBtn, pad 10 20, bg #333, col white, rad 6, toggle()
  open:
    bg #2271C1

Frame bg #1a1a1a, pad 12, rad 8, gap 4, hidden
  MenuBtn.open:
    visible
  Text "Menü Item 1", col white
  Text "Menü Item 2", col white

Der Validator prüft, dass der Name existiert und der State auf dem Trigger definiert ist — sonst zeigt das Lint-Underline im Editor einen Fehler.

Das Prinzip: States sind keine Ausnahmen vom Default — sie sind weitere Schichten Property-Values, eingerückt unter dem Element. Heute schreibst du sie direkt; ein State-Tab im Property-Panel ist geplant.
