Export & Deploy

Spec-Bundle für AI-Pipeline, mirror-build für direktes HTML

Wenn du fertig bist, willst du das Resultat irgendwo hinbringen. Mirror bietet zwei Wege: das Spec-Bundle übergibt dein Projekt einer AI-Pipeline, die produktionsreifen Framework-Code (React, Vue, Svelte oder Vanilla) erzeugt; das mirror-build-CLI baut direkt eine self-contained HTML-Datei, die du hochladen kannst — ohne weitere Build- Tools.

Spec-Bundle erzeugen — Mirror zu React/Vue/Svelte

In der Studio-Toolbar oben gibt es einen Export-Knopf (Pfeil-Down-Icon). Klick öffnet einen Dialog: Target wählen (React, Vue, Svelte, Vanilla), Snapshot ja/ nein (Render-Snapshot mit Computed-Styles für die AI), Output als Pfad.

Bestätigen erzeugt einen Ordner mit deinem Mirror-Source + DSL-Brief + Pipeline-Instructions + Target-Settings. Das Bundle ist self-contained — alles, was die AI braucht, um produktionsreifen Code zu generieren.

Mit Run Claude startest du die AI-Pipeline direkt aus Studio (AI-Bridge-Server muss laufen — siehe npm run ai-bridge in der README). Studio streamt die Pipeline-Phasen live und zeigt am Ende den generierten Code-Output.

Spec-Bundle erzeugen + Run Claude, ~2 min

mirror-build — eine HTML-Datei zum Hochladen

Wer keine Framework-Konvertierung braucht, sondern nur statisches HTML zum Deployen, nutzt das mirror-build- CLI: 

mirror-build app.mir
# → dist/app.html (self-contained, ~230 KB)

mirror-build my-project/ --minify
# → dist/index.html (minified, ~100 KB)

mirror-build app.mir --watch
# → rebuilds bei jeder Änderung

Das Output-HTML enthält allen JS und CSS inline — du brauchst keinen Build-Server, keine npm-Dependencies, kein Hosting-Setup. Hochladen und es läuft. Mit --external-css --external-js trennst du die Dateien, wenn dein Hoster Cache-Strategien erlaubt.

Das Prinzip: Mirror ist nicht nur Designwerkzeug, sondern Produktionsformat. Vom ersten Sketch bis zum hochgeladenen HTML kein Tool-Wechsel; oder eben mit AI-Pipeline weiter zu Framework-Code, je nach was du brauchst.
