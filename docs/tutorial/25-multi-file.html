Multi-File-Projekt

File-Operations im Explorer und Cross-File-Effekte

Kapitel 18 hat die Multi-File-Basis gezeigt — .tok anlegen, zwischen Files wechseln, Tokens projekt-weit nutzen. Hier geht es um die Operationen am File-Explorer (anlegen, umbenennen, löschen, duplizieren) und darum, wie sich Änderungen in einem File live auf alle anderen auswirken.

Projekt-Struktur

Ein Multi-File-Projekt sieht typischerweise so aus: 

my-app/
  data/        # *.yaml, *.yml — Datenquellen
  tokens/      # *.tok, *.tokens — Farben, Abstände, Radien
  components/  # *.com, *.components — wiederverwendbare Komponenten
  layouts/     # *.mir, *.mirror — Bildschirme & Templates
  screens/     # *.mir, *.mirror — Routen-Ziele
  app.mir      # Entry Point

Der Compiler verarbeitet die Files in dieser Reihenfolge — data/ zuerst, tokens/ zweitens, dann Komponenten, Layouts, Screens, am Ende der Entry. So sind beim Laden eines Layouts alle Tokens und Komponenten bereits bekannt.

File-Operations im Explorer

Im File-Explorer-Panel links siehst du den Projekt-Tree. Mit Rechtsklick auf einen Ordner: Neue Datei, Neuer Ordner. Auf einem File: Umbenennen (oder F2), Duplizieren, Löschen (mit Bestätigung).

Die Datei-Endung bestimmt die Datei-Art: .tok / .tokens für Tokens, .com / .components für Komponenten, .mir / .mirror für Layouts und Screens. Studio validiert beim Anlegen — falscher Inhaltstyp im falschen File-Typ produziert Lint-Warnungen.

Cross-File-Effekte — wenn Token oder Komponente sich ändert

Änderst du in tokens.tok einen Wert (etwa primary.bg: #2271C1 auf #10b981), rendern alle Layouts und Komponenten, die $primary referenzieren, im Preview sofort mit der neuen Farbe — auch wenn du gerade nicht in dem Layout-File bist.

Beispiel: drei Files, eine Token-Änderung wirkt überall: 

// tokens/colors.tok
primary.bg: #2271C1
panel.bg: #1a1a1a

// components/card.com
Card: bg $panel, pad 16, rad 8, gap 8
  Title: col white, fs 16
  Action as Button: bg $primary, col white, pad 8 16, rad 6

// layouts/dashboard.mir
Card
  Title "Heute"
  Action "Öffnen"

Änderst du primary.bg, sind alle Action-Buttons im ganzen Projekt sofort in der neuen Farbe. Studio führt einen SyncCoordinator, der sich um Re-Compile- und Re-Render-Reihenfolge kümmert; du musst nicht aktiv speichern oder reloaden.

Bei zirkulärer Komponenten-Inheritance (A as B und gleichzeitig B as A) erkennt der Validator den Zyklus und zeigt einen Lint-Marker auf der Definition.

Das Prinzip: Multi-File ist nicht „mehrere Codestellen synchron halten" — sondern eine Datei pro Verantwortung. Tokens hier, Komponenten dort, Layouts wo sie hingehören. Studio kümmert sich darum, dass Änderungen in einer Verantwortung bei den anderen ankommen.
