Studio bedienen

Bidirektionales Editieren, Property-Panel, Komponenten, Multi-File

Mirror Studio zeigt drei Sichten auf dieselbe Datei: Code, Preview und Property-Panel. Jede Geste in einer Sicht produziert sofort einen sichtbaren Diff in den anderen — du kannst tippen, ziehen, klicken, doppelklicken: alles landet im Code, und der Code rendert sofort. Dieses Kapitel zeigt die wichtigsten Workflows als kurze Loop-Aufnahmen.

Drop & Sync — Element aus der Palette

Im Components-Panel links siehst du die Bausteine: Frame, Text, Button, Icon und so weiter. Du ziehst sie direkt ins Preview oder in einen anderen Container. Während des Drags zeigt ein Drop-Indikator, wo das Element landet. Sobald du loslässt, erscheint die passende Mirror-Zeile im Editor.

Erst Frame aus der Palette in den leeren Canvas, dann Button in den Frame. Jeder Drop schreibt eine Mirror-Zeile mit den Default-Properties.

Inline-Edit — Text direkt im Preview ändern

Doppelklick auf einen Text im Preview macht ihn editierbar. Tippst du den neuen Text, wird er gespeichert sobald du Enter drückst oder anderswo hinklickst — und der Code-String in der entsprechenden Zeile updated sich gleich mit.

Doppelklick auf den Text im Preview öffnet den Inline-Editor. Die Eingabe ersetzt den String in der entsprechenden Code-Zeile.

Resize-Handles — Größe per Drag

Selektiere ein Element im Preview, dann erscheinen acht Resize-Handles an Ecken und Kanten. Ziehst du an einem Handle, ändert sich w oder h in der entsprechenden Zeile — Pixel-genau, mit Snap an Vielfache von 4.

SE-Eckhandle für Breite und Höhe gleichzeitig, S-Handle nur für Höhe. Die w- und h-Werte im Code laufen live mit.

Padding & Margin per Handle

Innerhalb eines selektierten Containers zeigen sich Padding-Handles an allen vier Seiten. Ziehst du sie nach innen, wird das Padding größer, nach außen kleiner. Margins gehen genauso — ziehe am Außenrand des Elements. Das Hold-Verhalten ist figma-ähnlich: Shift verändert nur eine Seite, sonst werden gegenüberliegende Seiten gespiegelt.

Erst Padding-Top von innen aufgezogen (pad-t 32), dann Margin-Top von außen (mar-t 24) — beide landen als eigene Properties in der Code-Zeile.

Property-Panel — Werte numerisch setzen

Rechts vom Preview ist das Property-Panel. Es zeigt für das selektierte Element alle gesetzten Properties — und alle ungesetzten, gruppiert nach Layout, Spacing, Typo, Color, Border, Effects. Änderst du einen Wert per Slider, Input oder Picker, wird die Zeile im Code an genau der richtigen Stelle ergänzt oder ersetzt.

Frame im Preview selektieren, dann der Reihe nach width, gap, bg und radius über die Eingabefelder im Property-Panel setzen — jeder Wert landet sofort in der Code-Zeile. (Padding und Margin gehen über die visuellen Handles, siehe oben.)

Drag-Reorder — Reihenfolge im Preview ändern

Innerhalb eines Containers ziehst du Kinder per Drag an eine neue Position. Während des Drags zeigt eine Linie an, zwischen welchen Elementen das gezogene landet. Sobald du loslässt, sortieren sich die entsprechenden Mirror-Zeilen im Code um.

Drei farbige Frames in einer Zeile — gelb wandert per Drag nach vorne, rot ans Ende. Die drei Frame-Zeilen im Code tauschen sich entsprechend um.

Code → Preview — die andere Richtung

Bisher ging es darum, was im Preview eine Spur im Code hinterlässt. Andersrum: tippst du Mirror-Zeilen direkt im Editor, baut das Preview live mit. Eine neue Zeile bedeutet sofort ein neues Element; ein Property-Wechsel ist als visueller Diff sichtbar, bevor der Cursor weiterspringt.

Vom leeren Canvas in vier Zeilen zur Card: Frame, zwei Texte, Button — jede Zeile rendert direkt nach dem Tippen.

Multi-File — Tokens, Komponenten, Layouts trennen

Größere Projekte teilst du auf mehrere Dateien auf: .tok für Tokens, .com für Komponenten, .mir für Layouts. Im File-Explorer links legst du sie an, mit Cmd+P springst du schnell zwischen ihnen. Tokens und Komponenten aus anderen Dateien sind überall im Projekt verfügbar — keine Imports.

tokens.tok wird angelegt mit drei Tokens, dann schaltet das Studio zurück nach index.mir. Die Frame-Zeile referenziert die Tokens via $primary und $card — Studio löst sie projekt-weit auf.

Das Prinzip: Studio ist kein eigenständiger Editor neben dem Code — es ist eine zweite Eingabe-Methode für genau dieselbe Datei. Was du im Preview tust, ist im Code lesbar; was du im Code änderst, ist im Preview sichtbar.
