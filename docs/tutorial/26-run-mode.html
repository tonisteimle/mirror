Run-Mode & Validierung

Interaktives Preview, Lint-Markers im Editor

Im Standard-Modus kannst du das Preview anschauen, Elemente selektieren und Properties ändern — aber Buttons reagieren nicht auf Klicks, States cyclen nicht. Im Run-Mode schaltet Studio das Preview in einen interaktiven Zustand: Buttons sind klickbar, States cyclen (vgl. 06-States), Form-Inputs sind editierbar (vgl. 08-Functions). Daneben hat der Editor Lint-Markers, die Fehler im Code direkt anzeigen.

Run-Mode toggeln — interaktives Preview

In der Toolbar oben gibt es einen Play-Knopf — Klick wechselt zwischen Edit-Mode und Run-Mode. Im Run-Mode wechselt der Cursor sich, Selektion-Indikatoren verschwinden, und das Preview verhält sich wie eine echte Anwendung:

  • Buttons reagieren auf Klick — toggle() wechselt den State, show(…) blendet Elemente ein
  • Inputs sind editierbar — Bind-Werte updaten Daten-Variablen in Echtzeit
  • States cyclen wie definiert — Tabs, Toggles, Multi-States funktionieren
  • Navigation und Routing zwischen Screens sind aktiv

Damit testest du das Verhalten ohne separates Build und Deployment. Zurück in den Edit-Mode mit demselben Toggle — State des Run-Modes wird zurückgesetzt.

Ein typischer Test-Kandidat:

name: ""
View
  Input bind name, placeholder "Wie heißt du?"
  if name
    Text "Hallo $name", fs 18, weight 600
  else
    Text "(noch keine Eingabe)", col #888

Im Edit-Mode siehst du den else-Pfad. Im Run-Mode kannst du tippen, der Bind aktualisiert $name, und der Text wechselt live auf „Hallo Anna".

Validierung im Editor — Lint-Markers

Während du tippst, validiert Studio den Code gegen das DSL-Schema. Fehler erscheinen als rote Wellenlinien unter dem Problem; Warnungen als gelbe. Hover über die Markierung zeigt einen Tooltip mit der Erklärung.

Beispiele: 

Frame bg #2271        // ✗ rot — ungültige Hex-Länge
Text fs bold          // ✗ gelb — bold ist weight, nicht fs
Card bg $unknown      // ✗ rot — Token nicht definiert
Btn pad 10            // ✓ grün — Standard-Padding

Hover über die rote/gelbe Wellenlinie zeigt einen Tooltip mit der Erklärung. Validierung läuft live; du musst nichts manuell triggern.

Lint-Status der ganzen Datei steht oben rechts: 0 Probleme bei sauberem Code, sonst Anzahl mit Klick- Drilldown auf die Zeilen.

Das Prinzip: Edit-Mode für das Bauen, Run-Mode für das Testen — beide Modi nutzen denselben Code. Validierung läuft live mit, du musst nichts manuell triggern; was rot ist, baut nicht; was gelb ist, baut, ist aber suboptimal.
