Tokens-Workflow

Definieren, im Code referenzieren, später als Token extrahieren oder umbenennen

Tokens sind benannte Werte — Farben, Abstände, Radien — die du einmal definierst und überall referenzierst (Syntax in 03-Tokens). Studio gibt dir drei Werkzeuge dazu: das einfache Definieren in einem .tok-File, das nachträgliche Extrahieren eines Hex-Werts in einen Token via ::-Trigger, und das Umbenennen eines Tokens mit cross-file Refactor.

Token definieren

Lege im Projekt ein tokens.tok-File an oder schreibe Tokens direkt am Anfang deines Layouts. Die Syntax ist immer dieselbe: 

primary.bg: #2271C1
muted.col: #888888
card.pad: 16
card.rad: 8
md.fs: 14

Der Suffix nach dem Punkt (bg, col, pad, …) sagt Studio, zu welchem Property-Typ dieser Token passt — der Token-Picker filtert später danach, und Validierung warnt wenn du $primary für ein Padding einsetzt.

In Komponenten und Layouts referenzierst du den Token ohne Suffix — Studio mappt automatisch zur passenden Property: bg $primary, pad $card, …

tokens.tok anlegen, Suffix-Mapping zeigen

Token-Extract — Hex-Wert nachträglich zu Token machen

Im Eifer des Gefechts hast du #2271C1 in fünf verschiedene Komponenten direkt eingetragen. Jetzt willst du diese Farbe in einen Token packen, damit du sie zentral steuern kannst.

Stelle den Cursor hinter einen Wert im Code und tippe :: — z. B. bg #2271C1::. Studio öffnet ein kleines Eingabefeld direkt neben dem Wert; tippe einen Token-Namen wie primary. Bestätigen mit Enter tut zweierlei: der Token wird in der zugehörigen .tok-Datei angelegt (primary.bg: #2271C1), und an der ursprünglichen Stelle steht jetzt bg $primary.

Andere Stellen mit derselben Hex-Farbe ersetzt du gezielt mit F2 auf dem Token-Namen oder per Find-and-Replace — ein automatisches projektweites Auto-Replace ist heute noch nicht da.

Token-Extract mit ::-Trigger

Token umbenennen — cross-file Refactor

Du hast einen Token blue definiert und willst ihn präziser primary nennen. Klick im Token-Panel auf den Namen, drücke F2, tippe den neuen Namen. Studio aktualisiert die Definition in tokens.tok und alle $blue-Referenzen in allen Layouts und Komponenten zu $primary.

Bei Mehrdeutigkeit (es gibt schon einen Token namens primary.col) warnt Studio und schlägt einen anderen Namen vor.

F2-Rename eines Tokens, alle Layouts updaten

Das Prinzip: Tokens sind kein extra Layer den du pflegen musst — sie entstehen aus dem Workflow heraus. Du tippst Hex-Werte solange das schneller ist; sobald sich Wiederholung zeigt, extrahierst du in einem Schritt.
