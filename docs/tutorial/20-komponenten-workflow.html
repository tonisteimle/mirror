Komponenten-Workflow

Extrahieren, Slots editieren, in eigene Files auslagern

Wenn du dasselbe Element-Muster mehrfach im Code wiederholst, wird es Zeit für eine Komponente (Syntax und Semantik dazu in 02-Komponenten). Studio macht die Extraktion in einem Schritt: du tippst Name:: vor die Eigenschaften, und Studio extrahiert die Definition, ersetzt alle Vorkommen durch Instanzen. Im Property-Panel und in der Components-Bibliothek arbeitest du danach mit der Komponente, nicht mit ihren Einzelteilen.

Komponente extrahieren mit dem ::-Trigger

Du hast eine Frame-Zeile mit Properties die du wiederverwenden willst. Setze den Cursor auf den Component-Namen und tippe :: direkt danach. Studio öffnet ein Popup: Als Komponente extrahieren? mit Eingabefeld für den Namen.

Bestätigst du mit Enter, geschieht zweierlei gleichzeitig: oben in der Datei (oder in components.com, wenn das File existiert) wird die Komponenten-Definition eingefügt mit allen Properties. Die ursprüngliche Zeile wird zur Instanz reduziert — nur Name plus eventueller Text-Inhalt.

Wenn das Projekt mehrere identische Frames hat (gleiche Properties, gleiche Children), zeigt Studio die Treffer und fragt: Auch diese ersetzen? Mit Häkchen pro Treffer kannst du selektiv refactoren.

::-Extract mit Auto-Replace, ~2 min

Slots — Default-Properties an Kind-Elementen

Eine Komponente kann benannte Slots für ihre Children haben. In der Definition gibt jeder Slot seine Default-Properties vor: 

Card: bg #1a1a1a, pad 16, rad 8, gap 8
  Title: col white, fs 16, weight 500
  Desc: col #888, fs 14
  Footer: hor, gap 8, mar-t 8

Im Property-Panel auf der Definition siehst du die Slots als nested Liste — klickst du Title an, ändert das Property-Panel die Properties dieses Slots. Was du hier änderst, wirkt auf alle Title-Slots aller Card-Instanzen.

An einer Instanz selbst kannst du Slot-Properties überschreiben (Instanz-Override) — Studio markiert die überschriebene Property mit einem Punkt im Panel, damit du den Override wiedererkennst.

Components-Bibliothek — Palette + eigene Komponenten

Das Components-Panel links zeigt zwei Bereiche: oben die Mirror-Primitives (Frame, Text, Button, Input, …), darunter alle Komponenten, die im aktuellen Projekt definiert sind. Beide kannst du per Drag & Drop in das Preview ziehen.

Der Unterschied: Primitives droppen die Default-Form (z. B. Frame w 100, h 100, bg #27272a); Komponenten droppen ihre Instanz mit Standard-Inhalt für die Slots („Title", „Desc", …). Damit experimentierst du sofort mit deinem eigenen Design-System.

Das Prinzip: Komponenten sind keine Code-Konstrukte mit Boilerplate, sondern eine Schreibkonvention. :: ist die Geste „mache aus diesem Element eine Komponente"; alles andere folgt.
