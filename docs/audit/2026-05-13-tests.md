# Mirror Tests — Audit, 2026-05-13

**Scope:** Three questions: (1) is there a sensible ordering / system in
the test layout, (2) is there a reasonable shared infrastructure, (3)
are there duplicate or outdated tests? Three parallel explore-agents,
each constrained to one dimension. Synthesizer spot-checked
surprising claims against the live tree and **corrected one false
positive** (the "10 orphan tests" claim — all 10 had already been
deleted; the agent worked from git history without on-disk
verification).

**Net conclusion:** The test surface is **large but not chaotic**. The
infrastructure layer is solid; the organization is messy because two
defensible taxonomies coexist without a documented decision rule. There
are zero genuine orphan tests on disk (prior sweeps were thorough).
What's actually broken is **discoverability**: no `tests/README.md`,
the canonical layer-doc lives in `docs/archive/`, and 8+ one-off
mini-directories make "where does this test go?" a folklore question.

---

## 1. Organization — three taxonomies coexisting

Mirror's tests live in two stacks: Vitest (`tests/`, 26 subdirs, ~600
files) and CDP-browser (`studio/test-api/suites/`, 40 subdirs, 363
files). The Vitest stack mixes three organizing principles:

- **Layer-based** (well-justified, documented): `tests/behavior/` (17),
  `tests/contract/` (16), `tests/differential/` (16),
  `tests/integration/` (25), `tests/runtime/` (5). These describe
  _which risk a test catches_, not what feature. Layer-doc in
  `docs/archive/test-layers.md` (archived — surfaced once, then
  forgotten).
- **Feature-based** (mirror-named in both stacks): 7 directory pairs
  exist in BOTH `tests/` and `studio/test-api/suites/` — `charts/`,
  `components/`, `data-binding/`, `primitives/`, `responsive/`,
  `styling/`, `compiler-verification/`. Implicit division of labor:
  Vitest = compile-output assertion, CDP = browser-workflow. Defensible
  but undocumented.
- **Subsystem-based**: `tests/cli/` (13), `tests/compiler/` (197),
  `tests/studio/` (206). These are the big buckets.

On top of those three: **one-off mini-directories** that look like
archaeology rather than system:

- `tests/parser/` — 1 file (`state-animations.test.ts`); belongs in
  `tests/compiler/parser-*`.
- `tests/ir/` — 2 files; belongs in `tests/compiler/ir-*`.
- `tests/policy/` — 1 file (DSL features-have-examples enforcement).
  Not feature/layer/subsystem — a project-policy linter.
- `tests/performance/` — 1 file, stub. Dormant.
- `tests/tauri-config/` — 1 file. Build-config infra, misplaced.
- `tests/utils/` — 1 test file plus 9 infrastructure files. The infra
  files don't belong in `tests/utils/` if `utils/` is also where helper
  modules live.
- `tests/helpers/` — 4 infrastructure files, **zero `.test.ts`**.
  Mis-named as a test-dir.
- `studio/test-api/suites/playmode/` — 1 file, stub. Dormant.
- `studio/test-api/suites/demos/` — 39 `.demo.ts` files (NOT `.test.ts`).
  These are **owner-exclusive tutorial recordings**, not tests; misplaced
  under `suites/` confuses test-discovery and runner-config.

**Top doc-gap:** No `tests/README.md`. The decision rule "do I add my
new test under `tests/behavior/` or `studio/test-api/suites/charts/`?"
is folklore. The archived layer-doc is the closest thing to authority.

## 2. Shared infrastructure — solid core, scattered helpers

What's centralized well:

- **`tests/utils/mirror-mount.ts`** (402 LOC) + **`mirror-test-adapter.ts`**
  (250 LOC) — vitest+jsdom adapter pair, single entry point for the
  10 ex-browser-test migrations. Consistent usage; no parallel mount
  strategy in `tests/`.
- **`compiler/testing/index.ts`** + **`render.ts`** — production-light
  test infra (parser/IR/DOM re-exports) consistently consumed by
  validation tests and `tests/fixtures/*/runner.test.ts`.
- **`tests/utils/setup.ts`** — jsdom polyfills (ResizeObserver,
  MutationObserver) + custom matcher registration. Single
  `setupFiles` entry in `vitest.config.ts`.

What's parallel / competing:

- **Mock-adapters: 4 hand-rolled files** at
  `studio/{autocomplete,sync,editor,panels/property}/adapters/mock-adapters.ts`
  (≈ 500 LOC each). No shared factory base — copy-paste style. Pattern
  is consistent (factory returning interface with `simulate*` /
  `getState` / `reset`) but a small base helper would cut 1500+ LOC.
- **Fixture runners: 16 parallel `tests/fixtures/*/runner.test.ts`**.
  Each re-implements extraction / normalization. One generic
  `runFixtureCategory(dir, expectation)` would collapse to a single
  loop.
- **Three test-helper homes for CDP**: `studio/test-api/helpers/`
  (centralized), `studio/test-api/suites/demos/_shared/` (per-suite),
  `studio/test-api/suites/preview-cdp/_shared/` (per-suite). The
  per-suite `_shared/` pattern competes with the centralized
  `helpers/` pattern — undocumented when to use which.
- **Two test APIs**: CDP `TestAPI` surface (interact/preview/assert/
  utils/dom) vs vitest+jsdom adapter (narrower, no drag/hover/focus).
  The adapter is one-way (CDP → Vitest); a bidirectional contract
  would help migrations.

What's missing:

- **`tests/README.md`** — see Section 1.
- **`@mirror/testing:createMockPort(portInterface)`** — would dedupe
  the 4 mock-adapters into a typed factory.

## 3. Duplicates &amp; outdated — clean (one false alarm)

**Zero orphan tests on disk.** The duplicate-audit agent flagged 10
files as orphans-of-deleted-systems (visual-alignment-detector,
visual-layout-converter, compile-helpers, compile-orchestrators,
react-converter, visual-measurements, measurement-calculator,
visual-auto-layout, pattern-detector, compiler-prelude-builder). All
10 verified **non-existent on disk** — they were deleted along with
their subjects in prior sweeps. The agent worked from git history of
deletion commits and mistook those for "files still floating". Prior
hygiene was thorough.

**tsc reports zero missing modules** — every test import resolves to a
live file. No dead-import orphans either.

**Intentional duplicate coverage** that should stay:

- `tests/compiler-verification/` (28 files, Vitest) vs
  `studio/test-api/suites/compiler-verification/` (33 files, CDP) —
  Vitest tests compile-output, CDP tests browser-rendering. Commit
  `932f2292` ("drop two skips redundant with browser stack") shows
  intentional de-duplication where possible. The rest is correct
  dual-stack coverage, not redundancy.

**121 `.skip` / `testWithSetupSkip` / `it.todo` occurrences across
both stacks.** Sampled set is documented (container-queries Lane A
pre-refactor pin, jsdom-limitations for CSS container queries, parser
hangs that have been fixed). The doc-cross-reference is good for
recent skips; older skips need periodic audit to ensure their lane is
still alive.

**Hypothesis / stress / fuzz tests** in `tests/compiler/` are real
coverage (property-based invariants, scalability edge cases, real-world
Mirror corpora). Not noise.

**Tests-that-test-the-test-framework** that exist (e.g.
`tests/utils/mirror-mount.test.ts`, `tests/studio/drag-drop/drag-test-runner.test.ts`,
`tests/studio/visual/grid-cell-math.test.ts`) are legitimate — they
test production utilities the test suite depends on, not meta-tests.

## Cross-cutting top recommendations

Ranked by leverage:

1. **Write `tests/README.md`** — the one-paragraph decision rule:
   _Vitest = compile-output without browser; CDP = mouse/keyboard or
   real-DOM workflow; feature dirs in both stacks are intentional dual
   coverage, not duplication._ Move `docs/archive/test-layers.md` out
   of archive and link from `tests/README.md`. Single highest-impact
   cleanup — unblocks every future "where does this test go" question.

2. **Fold mini-dirs into their natural homes:**
   - `tests/parser/` → `tests/compiler/parser-*` (1 file)
   - `tests/ir/` → `tests/compiler/ir-*` (2 files)
   - `tests/utils/*.test.ts` → keep at `tests/utils/`, but rename
     directory contents so the test/infra split is clear (or move
     the test files to a colocated subdir).
   - Delete `tests/performance/` (stub) and `tests/tauri-config/` (1
     file misplaced) unless actively populated.
   - Rename `tests/helpers/` → `tests/_infra/` (4 infra files, no
     tests — the leading underscore signals "not a test dir" to
     readers + most runners).

3. **Move `studio/test-api/suites/demos/` and `playmode/` out of
   `suites/`.** They're not tests; the discovery cost is paid every
   time a contributor browses `suites/`. Suggested path:
   `studio/test-api/demos/` (sibling to suites/), with a
   note that these are tutorial recordings owned by toni.

4. **Extract `runFixtureCategory()` from the 16 parallel fixture
   runners.** Single helper → reduce 16 near-identical
   `runner.test.ts` files to a thin wrapper each. Pattern matched
   prior decomp lanes — small slice, contained risk.

5. **Add a `mock-port` factory in `compiler/testing/`** (or a new
   `studio/_test-infra/mock-port.ts` if compiler/ should stay
   studio-agnostic). Migrate the 4 mock-adapters one at a time.
   Lower priority than 1-4 because the existing pattern is consistent
   and the cost is mostly LOC, not behavior risk.

   **Status 2026-05-13: deferred.** Detailed scoping showed the
   savings are smaller than the audit estimated. Each `MockFooPort`
   carries: (a) a port-specific `MockFooState` interface, (b) port-
   specific `simulate*` methods with unique signatures, (c) custom
   inspection helpers (e.g. `getEmittedDefinitions`), (d) `getState()`
   - `reset()` (the only uniform parts). A shared helper could only
     save (d) — roughly 5 LOC per port × ~15 ports = ~75 LOC, plus
     ~30 LOC helper = net ~45 LOC. The 4 files total 2033 LOC; the
     remaining ~1950 LOC is genuinely port-specific. With H1–H4
     delivering ~3500 LOC reduction and clear behavior wins, H5 is
     not worth the test-coverage-disruption risk at this leverage
     ratio. Re-open if the port count grows substantially or the
     simulate-pattern stabilizes.

## Out-of-scope (do not touch in this lane)

- The dual-stack `tests/` vs `studio/test-api/suites/` split itself.
  It's intentional and well-justified by the runtime difference
  (in-process vitest+jsdom vs out-of-process Chrome+CDP). Don't
  consolidate.
- The 121 skipped tests as a class. Most are documented via lane-doc
  cross-reference; selective audit is per-skip work, not a sweep.
- `studio/test-api/categories.ts` execution-time grouping. Different
  axis from file-system organization, both legitimate.
